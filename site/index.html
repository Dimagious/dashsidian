A dashboard inside an Obsidian note, built from six markdown blocks. Each block is a few lines of YAML. No JavaScript, and no Dataview.

Six blocks, one job each

What the blocks read

Frontmatter, through Obsidian's own metadata cache. The numbers come from properties you already keep in your notes. Nothing else to install, and nothing in your notes that a person cannot read a month later.

Install.md

Install

Dashy is in Obsidian's community plugin catalog.

  1. Settings›Community plugins›Browse
  2. Search for Dashy, then Install and Enable.
  3. Open a note and run Dashy: Insert block from the command palette (Ctrl/Cmd P).
  4. Pick a block. A working example lands at the cursor, ready to edit.
Which block?
  • tilesNavigation tiles with folder counts
  • statsNumber cards over a selection of notes
  • progressBars towards a goal
  • todayToday's date and the periodic notes
  • countdownDays until a date
  • heatmapA year of days, coloured by a number

The picker's own labels. Also on the plugin listing.

Habit tracker.md

A habit tracker from daily note checkboxes

Tick a checkbox property in a daily note, say gym: true, and that note already feeds a habit tracker. Any block that reads a field counts a ticked day as 1 and an unticked one as 0.

Habits.md
```stats
columns: 4
items:
  - { label: Gym days, source: Diary, field: gym, agg: sum }
  - { label: Longest gym streak, source: Diary, field: gym, agg: streak, unit: days }
  - { label: Gym this week, source: Diary, field: gym, agg: sum, period: week, compare: true, better: up }
  - { label: Gym this month, source: Diary, field: gym, agg: sum, period: month }
```

```heatmap
source: Diary
field: gym
color: orange
title: Gym
```

sum counts the ticked days. streak finds the longest run on record, not a run in progress, and an unticked day breaks it the way a missing note does. period: week narrows a card to the current week, which starts on Monday or Sunday as your language has it. compare: true sets it against the same days of last week, and with better: up a rise shows green. The heatmap paints the ticked days.

Written once

period counts from today. "This week" is always this week, and a period: year card starts over on 1 January without an edit.

Blocks/today.md

today: where the day starts

A row with today's date and links to the daily, weekly and monthly notes. Folders and filename formats come from Periodic Notes when you have it, and from the core Daily notes plugin otherwise; Dashy's own settings win over both. A note that does not exist yet gets a dimmed link, and clicking it creates the note.

today
```today
daily: true
weekly: true
monthly: true
```
renders as

Dashy's own New day starts at setting (00:00 to 06:00, midnight by default) decides what "today" means here, and for every other block on the page: period and compare windows, the heatmap's current day, countdown. It moves which day this block points to, not which day a note itself falls on: a note's own date is still its name or date_field.

Blocks/tiles.md

tiles: getting around

A grid of links into the vault, each with a live count of the notes in its folder. path also takes a Bases view, path: Vault.base#My view, which is the answer whenever you want a table.

tiles
```tiles
columns: 4
items:
  - { label: Inbox, path: Inbox, icon: 📥, badge: count }
  - { label: Diary, path: Diary, icon: 📔, badge: count, sub: one note a day }
  - { label: Books, path: Books, icon: 📚, badge: count }
  - { label: Sport, path: Diary, icon: 🏃, accent: true, sub: training log }
```
renders as

badge: count normally counts everything under path. Add tag, where, period and date_field to narrow it, the same keys stats uses below: a mail inbox tile that only counts this month's messages, a calendar tile that only counts today's events, both without an edit when the month turns.

tiles
```tiles
columns: 2
items:
  - { label: Mails, path: Mails, icon: 📥, date_field: start, period: month, badge: count }
  - { label: Events, path: Events, icon: 📅, date_field: start, period: 1d, badge: count }
```

These four keys only mean something next to badge: count; on a tile with no badge, or a custom one, they are ignored and warn.

Blocks/stats.md

stats: the numbers

One card per number, counted over the notes you select by source, tag or a single where condition. agg is one of count, sum, avg, min, max, latest, streak. trend: 30d draws the last thirty days next to the number, scaled between their own lowest and highest value.

stats
```stats
columns: 4
items:
  - { label: Days logged, source: Diary, agg: count, icon: 📔 }
  - { label: Average sleep, source: Diary, field: sleep_score, agg: avg, precision: 1, trend: 30d }
  - { label: Steps this week, source: Diary, field: steps, agg: sum, unit: steps, period: week }
  - { label: Best night, source: Diary, field: sleep_score, agg: max, trend: 90d }
  - { label: Longest streak, source: Diary, field: sleep_score, agg: streak, unit: days }
  - { label: Latest steps, source: Diary, field: steps, agg: latest, sub: most recent note }
  - { label: Great nights, source: Diary, where: "sleep_score >= 90", agg: count }
  - { label: Books read, source: Books, period: year, date_field: finished, agg: count, icon: 📚 }
```
renders as

period: week, month or year narrows a card to the current calendar one, ending today; period: 30d is a rolling count of days instead. A note's date is its name, as long as it starts with YYYY-MM-DD (2026-03-02 Monday and 2026-03-02_standup both count), unless date_field names a frontmatter date property instead. streak, latest and trend resolve a note's date the same way, whether or not period is even set, and two or more notes landing on the same day always count as that one day, not two.

A dash, not a zero

With nothing to count, a field aggregate like sum or avg shows a dash: "no notes at all" and "the sum is zero" are different answers. count has no such gap; an empty selection reads a plain 0, the same as everywhere else it counts notes. The dash also covers a field that no selected note actually carries, or one that holds text instead of a number: the card names which, rather than a zero that hides a typo.

Blocks/progress.md

progress: how far along

Bars towards a goal. Beating it shows as it is: 110% stays 110%, only the bar stops at full. period and date_field work as they do on stats, narrowing what the goal is measured against and feeding streak and latest too; "Books this year" reads a finished property, since a book is rarely named as a date.

progress
```progress
items:
  - { label: Days logged this year, source: Diary, agg: count, goal: 365, icon: 📔 }
  - { label: Books this year, source: Books, period: year, date_field: finished, agg: count, goal: 24, icon: 📚 }
  - { label: Steps, source: Diary, field: steps, agg: sum, goal: 3000000, unit: steps }
```

Blocks/heatmap.md

heatmap: the year

A cell per day, coloured by a number from frontmatter. A note's date is its name, as long as it starts with YYYY-MM-DD (2026-01-05 Monday counts, 2026-01-051 does not), unless date_field names a frontmatter date property instead. bands set the colour thresholds. Clicking a cell opens that day's note. The week starts where your language starts it.

heatmap
```heatmap
source: Diary
field: sleep_score
color: purple
bands: [90, 80, 70]
title: Sleep, last twelve months
```
renders as

Two or more notes landing on the same day paint one cell: their values sum, and a ticked or numeric note always outweighs a false one on the same day. A field nothing carries, or one that holds text rather than a number or a checkbox, is an error that says which, rather than an empty grid that looks like a note-taking gap.

A checkbox property works as field too: a ticked day paints its cell. That is the whole habit tracker.

Behaviour/Live redraw.md

It keeps up with the vault and the theme

Add a note, change a number, delete something, and every block on the page redraws. No reopening, no command to run. Colours are mixed from your theme's variables and accent, so a theme switch re-colours the dashboard with it.

The heatmap keeps its own place too: scroll it by hand and a redraw reopens there instead of snapping back to the end, and on a narrow note a fading edge shows which side still has months to scroll to.

Behaviour/Config errors.md

When the config is wrong, the block says so

A block that cannot draw explains why, in the note, next to what failed. An unknown key suggests the one you probably meant. A broken YAML line reports its line number. A filter that could not be read says the numbers below it are unfiltered. A field nobody wrote and a field that holds text instead of a number get different messages, not one generic "no data": the heatmap and the stats cards both say which.

A config with a mistake.md
```heatmap
source: Diary
feild: sleep_score
```

items:

Behaviour/AI agents.md

An AI agent can write the blocks for you

Two buttons in Dashy's settings. Each writes a file only when you press it.

  • Skill file in this vault writes .claude/skills/dashy/SKILL.md, which Claude Code picks up on its own.
  • AGENTS.md in the vault root writes the same reference where Cursor, Codex and others look for it. Only the fenced Dashy section is Dashy's; the rest of that file stays as it was.

Both are generated from schema.json, the file the plugin validates against, so the reference an agent reads matches what the plugin accepts.

Then you can ask

Make me a dashboard for my training log: a heatmap of distance, cards for weekly volume and longest run, and a countdown to the marathon in May.

Behaviour/Languages.md

Five languages

The plugin speaks the language of your Obsidian interface, or the one you pick in its settings. Anything a translation misses falls back to English. Dates, month names and the first day of the week come from Obsidian itself.

What it leaves out.md

What it leaves out

The list stops at six blocks on purpose. Dashy does not draw:

  • charts (see Obsidian Charts)
  • tables and queries (Bases, Dataview)
  • kanban boards or task lists

where takes one condition. If that stops you building something, say what you tried; that is the quickest way to change it.

Questions.md

Questions

Do I need Dataview or any other plugin?

No. Dashy reads frontmatter through Obsidian's own metadata cache. If you use Periodic Notes, the today block reads its folders and formats; it works with the core Daily notes plugin too.

Does it work on my phone?

Yes. The plugin is not desktop-only, and the blocks fit a narrow screen.

How does a block know a note's date?

From the note's name, as long as it starts with YYYY-MM-DD: 2026-03-02 Monday and 2026-03-02_standup both count. date_field can name a frontmatter date property instead on any block that counts by day, which is how a book note counts by the day it was finished. Notes without a date are left out of anything that counts by day.

Will it write to my notes?

The blocks only read. Files get written when you ask: Insert block puts an example at your cursor, the settings buttons write the agent reference, and clicking a dimmed link in today creates that periodic note.

Does it match my theme?

Yes. No colour is hard-coded; every surface is mixed from your theme's variables and accent colour.

How do I report a bug?

The settings tab has a row for it. It opens a GitHub issue with your plugin and Obsidian versions already filled in. Or go straight to the issue tracker.

If Dashy is useful to you

Dashy is free and made by one developer. A star on GitHub tells others the plugin is worth a look, and a coffee is a way to say thanks.
