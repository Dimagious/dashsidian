How it behaves

  • Going past the goal is shown as it is, 125% stays 125%; only the bar itself stops at full.
  • count over nothing reads a plain 0 and an empty bar; every other aggregate, and streak or current_streak with a field set, shows a dash instead: "no data" and "zero" are different answers.
  • streak counts the longest run of consecutive days on record; label the bar "Best streak" or "Longest streak". current_streak counts the run going on now, label it "Current streak" or "Days in a row": today never breaks it, a day not filled yet leaves the run counted up to yesterday, and only a gap on yesterday or earlier resets it. It counts within the selection after period, where, tag and source, so period: month stops it at the first of the month.
  • period narrows to a calendar week, month, year or a rolling Nd, ending today, or to a fixed window, below. A note's date is its name, as long as it starts with YYYY-MM-DD (2026-03-02 Monday counts, 2026-03-021 does not) or with a date in date_format or in the Daily notes day format, unless date_field names a property instead; a note with no date under either rule is left out before counting.
  • at_least/at_most turn streak into a threshold: a day counts only when its notes' field values, summed for that day, satisfy the bound, at_least: 5000 on steps for example. days: weekdays makes Saturday and Sunday transparent for streak and current_streak: they neither break the run nor extend it, whatever they hold, so a Friday followed by a Monday is a run of two. skip_field does the same for a day any note marks special, vacation: true or sick: flu for example, and combines with days: weekdays. All three keys apply to agg: streak and agg: current_streak only and are ignored on every other aggregate.
  • source, tag, where, period, date_field and date_format written at the block root, next to items:, apply to every bar, so a folder shared by the whole block is written once. A bar's own source, tag, period, date_field or date_format replaces the root's for that bar; where is the exception: the root's conditions and the bar's own both hold. A root folder that does not exist, a root where or period that cannot be read, a blank root source or tag, a root date_field that no note selected under period has a date in, or a root date_format that none of the notes its bars select fits is reported once for the block, not once per bar. A bar's own source: or tag: left empty still replaces the root's, so the bar reads the whole vault or drops the tag filter, and it warns: to inherit the root's value, remove the key. Without items: the block is a single bar and these keys are simply its own.
  • Daily notes named another way, like 05.10.2026, are read in the day format set in the Daily notes or Periodic Notes settings, with no key at all. Without that setting, name the format: date_format: DD.MM.YYYY. A time after the date is fine (2026-10-05-14:30), but an order that could be read two ways, like 05-10-2026, is never guessed: without a format it is not a date.
  • A monthly review: in a note named 2026-10, period: note measures the goal against that month and no other: { label: Running, field: distance_km, agg: sum, goal: 200, unit: km, period: note }. period: 2026-Q4 or period: { from: 2026-09-01, to: 2026-11-30 } names a window outright. The name is read in the formats set in Periodic Notes for each period (one switched on there with no format saved, in the plugin's default, so a week is the locale week gggg-[W]ww), the day falling back to Daily notes, then as ISO: YYYY-MM-DD, GGGG-[W]WW, YYYY-MM, YYYY-[Q]Q, YYYY, the day first, so 2026 never takes 2026-10. A note named otherwise is an error that lists those formats; nothing is guessed. current_streak counts back from the window's last day. A window already over does not forgive that day the way a running one forgives today: a closed week with its last day unticked reads 0. A window that has not started yet draws no bars, only the day it starts.
